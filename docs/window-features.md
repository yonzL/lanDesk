# 远程会话窗口：功能对照表（RustDesk / SubnetDesk / lanDesk）

用途：给"要不要做某个功能"提供一张完整清单。图例见文末。

- **RustDesk**：我们的基线（1.5.1）上游。lanDesk 的 Flutter 界面**就是**这套 UI，所以"上游有"的功能在界面上基本都在。
- **SubnetDesk**：RustDesk **2.0** 的分支（`zibo-chen/SubnetDesk`），同类产品（局域网直连）。
- **lanDesk**：本仓库现在的实际状态。判据是"直连 + keyauth 会话下能不能用"，而不是"UI 里有没有按钮"。

## 7. lanDesk 独有（SubnetDesk 也没有）

| 能力 | 说明 |
|---|---|
| 双向密钥证明（ed25519 全局密钥对） | SubnetDesk 只证服务端，客户端靠用户名/密码（Argon2id） |
| 主机指纹 TOFU + "已验证"标记 | 两边都有 TOFU；我们额外有"人工核对后标记" |
| 服务端绑**公钥集合**、逐台撤销、免重启 | SubnetDesk 无此概念 |
| 来源网段白名单（默认只收私有网段） | 两边都有，语义接近 |
| 监听监督循环 + `landesk-status.json` + `--landesk-doctor` | SubnetDesk 有类似的状态机，没有 doctor |
| 地址簿 CSV 覆盖式合并 + 每台钉身份 | SubnetDesk 有地址簿，无 CSV 语义 |
| 只发 Flutter、无公网代码 | 它保留了 hbbs http 等 |

## 需要你决定的几处

1. **文件传输窗口**：现在只有 CLI 推送。要不要在会话窗口/地址簿里加"选目录传文件"的界面？（这是我们与上游最大的可见差距）
2. **拖文件到会话窗口**：插件已在包里，接上约需一个 `DesktopDrop` 回调。
3. **多标签页**：现在一台机器一个窗口。上游能在单窗口开多个标签、拖出成新窗口——我们的"同进程多引擎 + 无崩溃隔离"意味着这层要谨慎做。
4. **终端 / 摄像头 / 端口转发 / 远程打印**：都还没接。要按需求挑。
5. **阻止输入 / 隐私模式 / 交换方向**：UI 在但没验，Windows 下都依赖驱动或额外权限。
